# ChatNU

ChatNU is a native Android messenger with a self-hosted Node.js server stack.

## What is implemented

### Messaging

- Native Android client built as a normal Gradle `:app` module.
- Username/password registration and login.
- Argon2id password/recovery-code hashing.
- Short-lived JWT access tokens, rotating refresh tokens and per-device session revocation.
- User search, direct conversations and group conversations.
- Persistent PostgreSQL message history, read receipts and realtime WebSocket delivery through Redis fan-out.
- Versioned Prisma migrations.

### End-to-end encryption

New Android messages use device-based client-side E2EE:

- RSA-3072 device identity keys are generated inside Android Keystore.
- Every message gets a fresh AES-256-GCM content key.
- That content key is wrapped independently for every active conversation device using RSA-OAEP/SHA-256.
- The server stores only opaque ciphertext envelopes and per-device wrapped keys.
- Legacy reversible `CryptoEngine` messages remain readable for compatibility, but new production sends do not use the legacy format.

This is real client-side E2EE, but it is not Signal Protocol/Double Ratchet and does not claim Signal-grade forward secrecy or an external security audit. See `SECURITY_MODEL.md`.

### Attachments

- Android can select photos, videos and arbitrary documents through the system picker.
- Attachment bytes are AES-256-GCM encrypted on-device before upload.
- Only encrypted blobs are stored in the private attachment Docker volume.
- Attachment keys travel inside the encrypted message payload.
- Opening an attachment downloads and decrypts it into private Android cache and exposes it through `FileProvider` only for the selected viewer.

### Calls

- Real one-to-one WebRTC voice and video calls.
- Authenticated offer/answer/ICE signaling over the existing ChatNU WebSocket.
- Mute, camera toggle, speaker routing and local/remote video rendering.
- Android active-call foreground service.
- Self-hosted Coturn support for NAT traversal.
- Short-lived TURN REST credentials generated by the API.
- Brief pending-call storage for peers that reconnect after the offer.

Group calling is intentionally not implemented. A reliable production group-call design should use an SFU, not a pretend mesh implementation.

### Push

FCM support is optional. When configured, push payloads contain routing IDs only; message plaintext and encryption keys are not sent through Firebase. The app still builds and works without Firebase configuration, with realtime delivery while connected.

## Start the server

Requirements: Docker Engine + Docker Compose v2.

```bash
chmod +x scripts/chatnu.sh
./scripts/chatnu.sh up
curl http://127.0.0.1:3000/health
```

If `.env` does not exist, the helper creates it with random PostgreSQL, JWT and TURN secrets and permissions `0600`.

Useful commands:

```bash
./scripts/chatnu.sh status
./scripts/chatnu.sh logs
./scripts/chatnu.sh restart
./scripts/chatnu.sh down
./scripts/chatnu.sh reset   # destroys DB, Redis and attachment volumes
```

The API is intentionally bound to `127.0.0.1:3000`. PostgreSQL and Redis are not published on host ports. Put Nginx/Caddy in front of the API for HTTPS/WSS.

For reliable WebRTC through restrictive NATs, set a public `TURN_HOST`, expose the Coturn ports described in `DEPLOYMENT.md`, and keep `TURN_SHARED_SECRET` private.

## Android endpoints

Debug builds default to the emulator host:

```text
http://10.0.2.2:3000/
ws://10.0.2.2:3000/realtime
```

Release defaults are:

```text
https://api.devnu.ir/
wss://api.devnu.ir/realtime
```

Override at build time with:

```bash
CHATNU_API_URL=https://chat.example.com/ \
CHATNU_WS_URL=wss://chat.example.com/realtime \
gradle :app:assembleDebug
```

Current Android version: `1.1.0` (`versionCode 3`).

## Production release signing

The release workflow builds signed APK and AAB artifacts after these GitHub Actions secrets are configured:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

At Gradle runtime the workflow maps those secrets to the `CHATNU_KEYSTORE_*` environment variables expected by `app/build.gradle.kts`.

The production signing keystore must be long-lived and controlled by the app owner. Losing it breaks the normal update path for already installed production builds.

Firebase Android client values can also be supplied as `FIREBASE_APP_ID`, `FIREBASE_API_KEY`, `FIREBASE_PROJECT_ID`, and `FIREBASE_SENDER_ID` when push is enabled. They are not required for a non-FCM build.

## Repository layout

- `app/` Android application
- `server/` Node.js/TypeScript API and Prisma schema/migrations
- `docker-compose.yml` PostgreSQL + Redis + API + self-hosted TURN service
- `scripts/chatnu.sh` server lifecycle helper
- `DEPLOYMENT.md` production deployment, reverse proxy, TURN and backup instructions
- `API_CONTRACT.md` public API summary
- `SECURITY_MODEL.md` implemented guarantees and explicit security boundaries
- `.github/workflows/ci.yml` server, Docker smoke and Android APK validation
- `.github/workflows/release.yml` signed APK/AAB release pipeline
